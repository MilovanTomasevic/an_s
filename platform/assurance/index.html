advanexus Assurance

Investigate a supported outcome through the available evidence behind it.

Assurance is a permission-aware, read-optimised layer for exploring supported operational evidence. It does not replace the canonical source or manufacture history that was never recorded.

Explore the evidence model →

01

A projection for investigation, not a second system of record.

Sources, SQL Console, Datasets, Analytics, Sandbox, Pipelines, IAM and other modules retain canonical ownership. Assurance normalises supported events, relations and snapshots into a bounded read model that can be rebuilt without erasing Assurance-owned workflow objects.

02

Tenant Assurance keeps the organisational view and project boundary together.

Each tenant has one tenant-wide Assurance read model. Supported overviews, searches and drill-downs derive allowed projects from current membership and permission scope, apply a bounded time range and label signals whose project, environment or module filters differ.

01Overview trends, outcome and module distributions

02Actor contribution with direct evidence drill

03Projection health, completeness and freshness signals

04Explicit loading, empty, restricted, stale, truncated and safe-error states

03

Evidence Explorer moves from a question to an exact record.

Bounded free text and structured actor, project, module, entity, action, outcome, correlation, run, integrity, completeness and time filters return stable cursor-paginated results. Exact detail lookup never depends on the currently visible top-N page.

01Table, timeline, grouped and bounded graph views

02Private Saved Views that never widen the opener's scope

03Permission-approved deep links back to canonical modules

04

Entity 360 and User 360 preserve the evidence behind the summary.

Entity 360 combines lifecycle, owner, version, timeline, relations, runs, findings, cases and reproducibility criteria for an authorised asset or run. User 360 adds a drillable evidence footprint by module, action, outcome, project, asset and day.

01User 360 is not an employee productivity, quality or HR score.

02Counts remain explainable through the exact events that support them.

03Hidden projects do not leak names, nodes or unauthorised totals.

05

Version comparison distinguishes missing from unchanged.

Two exact evidence versions can expose recorded metadata, state, schema, configuration and hash differences with left/right values and bounded truncation. Missing historical snapshots remain unavailable; they are not reconstructed from a hash or current state.

06

Execution Story preserves attempts, retries and partial outcomes.

Authorised events are connected through run, correlation, entity or source-event identity and ordered chronologically. Retry, parallel attempt, cancellation, partial success and failure remain separate facts rather than one simplified terminal label.

07

Evidence Graph expands only known, authorised relationships.

Upstream, downstream or bidirectional exploration uses bounded depth and node/edge limits. Each supported expansion repeats scope checks; the graph is a visual projection of recorded relations, not a claim of universal lineage or global shortest-path discovery.

QueryExecution → DatasetVersion → AnalyticsRun → Artifact

08

Turn a signal into controlled work.

Deterministic Findings retain the evidence state that produced them and support assignment, acknowledgement, remediation, resolution, accepted exception and explained false-positive disposition. Cases add owner, priority, status, due/closure context and validated links without changing the canonical event.

01Case links are resolved server-side in the same tenant/project scope.

02Current browser workflow does not expose a complete comment, task and link editor on every surface.

03Controls remain read-only coverage signals, not automatic certification.

09

Reproducibility is an explicit criterion set, not a confidence score.

Exact input/version, query or code/config hash, runtime environment, permission/RLS context, output artifact and integrity state are assessed separately. The result is reproducible, partially reproducible, not reproducible or not assessed, with missing criteria visible.

10

Integrity strength follows the source.

Verified, unverified, broken, legacy-without-integrity-data and pending are materially different states. A valid projection hash does not transform a legacy source into verified business history, and a successful Integrity Run may still contain unverified, pending or legacy records.

11

Package only the authorised scope.

Evidence Packages assemble only the authorised scope into bounded HTML, PDF, CSV, JSON, NDJSON or ZIP outputs with manifest and checksum metadata.

Technical export only — not automatically digitally signed, WORM protected, PDF/A or legally conclusive.

  1. Generation follows a bounded asynchronous reporting path with durable status.

  2. Download rechecks current permission, scope, status, expiry, token, size and ZIP SHA-256.

  3. Stored-package verification checks manifest, member names, sizes and checksums.

  4. Preview is the authority for actual package scope; report type is metadata, not a hidden renderer.

12

Sensitive data follows one versioned policy.

Credentials, tokens, cookies, DSN userinfo and related material are redacted before persistence, DTO rendering and package generation. Technical-context permission does not automatically grant sensitive reveal, and SQL or code is cleaned before safe hashing.

13

System Assurance uses a separate, narrow privileged path.

The admin application uses sanitised control-side projections for cross-tenant overview and search. Exact tenant detail requires a persisted reason-bound, time-bounded privileged-access session and an exact event capability; the gateway opens one tenant database and reads one matching normalised event under a statement timeout.

01Default detail is redacted; one-response sensitive reveal requires an additional permission and high-value evidence event.

02Concurrent revoke, expiry, suspended tenant or identity mismatch fails closed before or after the tenant read.

03The gateway is not raw SQL, bulk export, arbitrary canonical-table access or a general artifact channel.

14

Projection freshness and history remain observable.

Live DomainEvents and transactional outbox records feed separate tenant, control and sanitised-mirror checkpoints. Projection is durable at-least-once with idempotent source identity—not a marketing exactly-once claim. Bounded backfill, rebuild and reconciliation expose candidates, duplicates, unknown types, failures, legacy records and orphan relations.
