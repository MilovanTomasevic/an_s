受治理的数据集

将数据定义转化为具有明确血缘的版本化资产。

Dataset 将探索性 SQL 与可复用数据契约分离。其稳定身份、不可变版本和语义元数据为报告建立受控基础，同时不隐藏来源血缘。

查看受控 Analytics →

01

Dataset 是契约，而不是改名后的查询结果。

Dataset 连接来源与查询血缘、规范化 SQL、列与语义元数据、生命周期状态和不可变 DatasetVersion。SavedQuery 仍是可编辑 SQL；Report 描述分析意图。

01Dataset 可以源自 SQL Console 执行、SavedQuery、物理表或受控转换。

02DatasetColumn 记录准确版本的已知架构与概要元数据。

03SQL Console 提升会让权威 Dataset 与 Analytics 语义投影保持一致，但不会合并二者的所有权边界。

02

版本表示准确的契约状态。

更改 Dataset 拥有的 SQL、连接、来源、架构、列或列元数据会创建新的 DatasetVersion。Analytics 指标、RLS 和报告权限仍是独立契约。现有 ReportVersion 保持固定，直到用户验证新的 DatasetVersion 并保存新的 ReportVersion。

Report v4 → Dataset v2 · Report v5 → Dataset v2 · Report v6 → Dataset v3

03

虚拟版本不会自动冻结数据行。

当 DatasetVersion 存储实时 SQL 契约时，后续运行可以在使用同一定义的同时读取更新的来源行。准确重建历史结果需要运行哈希和保留制品，或明确的物化快照。

04

比较显示已记录变更，而不虚构影响。

用户可以比较规范化 SQL、列、类型和已知血缘元数据。对于从未记录的关系，平台不会宣称能够提供通用的下游业务影响分析。

01准确的左右版本身份与 SHA-256 SQL 契约

02感知行号并显示增删的 SQL 比较

03列、类型、可空性和已知元数据变更

04明确的未变更、已变更、新增、移除和不可用状态

05

Dataset 与 Analytics 保持职责分离。

Dataset 拥有稳定数据资产及其版本。Analytics 拥有指标、RLS、资源权限、Query Context 和报告执行。该区分使治理边界可审阅。

06

演进需要明确的接受决策。

新的 DatasetVersion 不会静默移动现有报告。用户比较契约、验证维度和指标、预览生成的查询，随后保存绑定到已接受 DatasetVersion 的新 ReportVersion。旧 ReportVersion 和运行保留原始绑定。

  1. 01

    比较 Dataset v2 与 v3。

  2. 02

    确认变更的 SQL、列与类型。

  3. 03

    针对 Dataset v3 打开报告草稿。

  4. 04

    验证元数据并编译只读 SQL。

  5. 05

    在当前权限与 RLS 上下文中预览。

  6. 06

    仅在接受后保存 Report v6 → Dataset v3。
