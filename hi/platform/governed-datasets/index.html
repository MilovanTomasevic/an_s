शासित datasets

डेटा परिभाषाओं को स्पष्ट वंशावली वाली संस्करणबद्ध परिसंपत्तियों में बदलें।

Dataset अन्वेषणात्मक SQL को पुनः प्रयोज्य डेटा अनुबंध से अलग करता है। इसकी स्थिर पहचान, अपरिवर्तनीय संस्करण और अर्थगत मेटाडेटा, स्रोत वंशावली को छिपाए बिना रिपोर्टों के लिए नियंत्रित आधार बनाते हैं।

नियंत्रित देखें Analytics →

01

Dataset एक अनुबंध है, केवल नया नाम दिया गया क्वेरी परिणाम नहीं।

Dataset जुड़े हुए Source और क्वेरी वंशावली, सामान्यीकृत SQL, स्तंभ और अर्थगत मेटाडाटा, जीवनचक्र स्थिति और अपरिवर्तनीय DatasetVersions को जोड़ता है। SavedQuery संपादन-योग्य SQL रखता है; Report विश्लेषणात्मक आशय को दर्शाता है।

01Dataset, SQL Console निष्पादन, SavedQuery, भौतिक तालिका या नियंत्रित रूपांतरण से उत्पन्न हो सकता है।

02DatasetColumn रिकॉर्ड सटीक संस्करण के लिए स्कीमा और प्रोफ़ाइल मेटाडाटा जाना जाता है।

03SQL Console पदोन्नति ने अपने स्वामित्व सीमाओं को पार किए बिना कैनोनिकल Dataset को Analytics के साथ संरेखित किया।

02

संस्करण का मतलब सटीक अनुबंध राज्य है।

बदलना Dataset-स्वामित्व वाला SQL, जुड़ना, स्रोत, स्कीमा, स्तंभ या स्तंभ मेटाडाटा एक नया DatasetVersion बनाता है। Analytics मेट्रिक्स, RLS और रिपोर्ट अनुमतियां अलग-अलग अनुबंध बनाती हैं। मौजूदा ReportVersions एक उपयोगकर्ता को नए DatasetVersion को मान्य करने तक पिन किया गया और एक नया ReportVersion बचाता है।

Report v4 → Dataset v2 · Report v5 → Dataset v2 · Report v6 → Dataset v3

03

एक आभासी संस्करण स्वचालित रूप से पंक्तियों को फ्रीज नहीं करता है।

जब एक DatasetVersion एक लाइव स्टोर करता है SQL अनुबंध, बाद में रन उसी परिभाषा का उपयोग करते समय नए स्रोत पंक्तियों को पढ़ सकते हैं। सटीक ऐतिहासिक परिणाम पुनर्निर्माण के लिए रन हैश की आवश्यकता होती है और कलाकृति या एक स्पष्ट सामग्रीकृत स्नैपशॉट बनाए रखा जाता है।

04

तुलना में परिवर्तन दर्ज किए गए दिखाता है, प्रभाव का आविष्कार नहीं किया गया है।

उपयोगकर्ता सामान्यीकृत SQL, स्तंभों, प्रकारों और ज्ञात वंशानुगत मेटाडाटा की तुलना कर सकते हैं। मंच उन रिश्तों के लिए सार्वभौमिक डाउनस्ट्रीम व्यवसाय प्रभाव विश्लेषण का दावा नहीं करता है जिन्हें कभी दर्ज नहीं किया गया था।

01सटीक बाएं / दाएं संस्करण पहचान और SHA-256 SQL अनुबंध

02लाइन-एवेयर SQL सम्मिलन और हटाने के साथ तुलना

03स्तंभ, प्रकार, रिक्त-स्वीकार्य और ज्ञात मेटाडाटा परिवर्तन

04एक्सप्लिकिट अपरिवर्तित, बदल गया, जोड़ा गया, हटा दिया गया और अनुपलब्ध राज्यों

05

Dataset और Analytics अलग जिम्मेदारियों को रखते हैं।

Dataset स्थिर डेटा परिसंपत्ति और संस्करणों का मालिक है। Analytics मीट्रिक, RLS, संसाधन अनुमति, क्वेरी संदर्भ और रिपोर्ट निष्पादन का मालिक है। भेद प्रशासन सीमाओं की समीक्षा करने योग्य रखता है।

06

विकास एक स्पष्ट स्वीकृति निर्णय है।

नया DatasetVersion मौजूदा Reports को चुपचाप नहीं बदलता। उपयोगकर्ता अनुबंधों की तुलना करता है, आयाम और मैट्रिक मान्य करता है, उत्पन्न क्वेरी का पूर्वावलोकन करता है और स्वीकृत DatasetVersion से बँधा नया ReportVersion सहेजता है। पुराने ReportVersions और रन अपनी मूल बाइंडिंग बनाए रखते हैं।

  1. 01

    Dataset v2 की v3 से तुलना करें।

  2. 02

    बदलना SQL, कॉलम और प्रकार की पुष्टि करें।

  3. 03

    रिपोर्ट के खिलाफ Dataset v3 ड्राफ्ट खोलें।

  4. 04

    मेटाडाटा को मान्य करें और केवल पढ़ने योग्य SQL को संकलित करें।

  5. 05

    वर्तमान अनुमति और RLS संदर्भ के तहत पूर्वावलोकन।

  6. 06

    सहेजें Report v6 → Dataset v3 केवल स्वीकृति के बाद।

आगे अन्वेषण करें

संबंधित दृष्टिकोण

नियंत्रित विश्लेषण डेटा अनुबंध को स्थिर करें। निष्पादन दर्ज करें। परिणाम समझाएँ।

नियंत्रित विश्लेषण रिपोर्ट को सटीक DatasetVersion से बाँधता है, सर्वर पर Query Context को मान्य करता है और समर्थित परिणाम के पीछे की अनुमति, RLS, फ़िल्टर, बाइंडिंग और कलाकृति संदर्भ को संरक्षित रखता है।

→ डेटा गुणवत्ता गुणवत्ता को निष्पादन का हिस्सा बनाएँ, बाद की काग़ज़ी कार्यवाही नहीं।

Data Quality स्रोत-उन्मुख अपेक्षाओं को स्पष्ट सफलता शर्त, संरक्षित QualityRun और सीमित विफलता साक्ष्य वाले पुनरावृत्ति-योग्य SQL अभिकथनों में बदलता है।

→ शासित विश्लेषण प्रसव जानें कि किस डेटा अनुबंध, अनुमति, फ़िल्टर और ReportVersion ने परिणाम बनाया।

चार्ट या डैशबोर्ड को उन सटीक संस्करण बाइंडिंग और रन संदर्भ के साथ वितरित करें जिनसे उसे बाद में समझाया जा सके, और रनटाइम फ़िल्टर को सर्वर-स्वामित्व वाले RLS से अलग रखें।

→
