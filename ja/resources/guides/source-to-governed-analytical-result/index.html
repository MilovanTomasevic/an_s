運用ガイド・データライフサイクル

既知の入力から、ガバナンスされた分析結果へ。

繰り返し生成する分析結果について、別々の正規モジュールを横断して既知の入力、品質、バージョン、権限、実行コンテキストを保持する必要がある場合に、このワークフローを使用します。

01

意思決定上の問い

チームは、結果の背後にある正確な入力、受入済み品質結果、Dataset 契約、Report 契約、実行記録を特定できますか。それとも、いずれかの受け渡しが依然として非公式ですか。

02

使用するオブジェクトと制御

このワークフローでは、異なるモジュールが所有するオブジェクトを使用します。各参照がストーリーを接続するのであり、1 つの合成実行にまとめることはありません。

入力アイデンティティ

サーバー管理の Tenant／Project スコープを持つ Project スコープの Source、または不変 FileVersion。

公開と品質

任意の TransformationRun と TableVersion、その後に Source 指向の QualityRule と永続化された QualityRun。

ガバナンスされたデータ契約

Source／クエリリネージュと記録済み列メタデータを持つ Dataset および正確な DatasetVersion。

分析契約

その DatasetVersion に結び付いた ReportVersion と、現在の権限、RLS、実行時フィルターコンテキスト下の AnalyticsRun。

03

運用フロー

各遷移を明示的に実行し、担当モジュールが返したアイデンティティを保持します。

  1. 01

    入力を登録する

    Project Source を選択するか、ファイルをアップロード/インポートして、解釈前に不変 FileVersion と SHA-256 アイデンティティを確立します。

  2. 02

    実行前に検査する

    Source メタデータ、またはファイルパーサー、区切り文字、ヘッダー、スキーマプレビュー、警告を確認します。解釈が未解決の間は、ファイル変換をキューに入れません。

  3. 03

    必要に応じて管理テーブルを公開する

    シャドー物理的なバージョンに読み込みし、行／スキーマの結果を検証し、成功した場合に限り安定した Sandbox エイリアスを昇格します。

  4. 04

    品質判断を実行する

    受入済みアサーションを実行し、その QualityRun を保持します。プレビューは有用なフィードバックですが、永続的な実行記録ではありません。

  5. 05

    ガバナンスされた Dataset を昇格する

    SQL またはテーブルリネージュを、安定した Dataset アイデンティティおよび正確な不変 DatasetVersion として受け入れます。

  6. 06

    分析契約を受け入れる

    ディメンションと指標を選択し、メタデータを検証し、サーバー管理の読み取り専用の SQL をコンパイルし、正確な DatasetVersion に結び付いた ReportVersion を保存します。

  7. 07

    実行して検査する

    Report を実行し、結果を利用する前に、AnalyticsRun の状態、バインディング、フィルター、権限／RLS コンテキスト、診断情報、成果物、切り詰めを確認します。

04

失敗および部分的な経路

失敗は、試行したアクションを所有するモジュールが処理します。後続画面がその終端状態を上書きしたり、別の意味に解釈したりしてはなりません。

事前検査または変換が失敗する

新しいエイリアスバージョンは昇格せず、以前の安定テーブルが現行のまま残り、試行した TransformationRun は検査可能な状態を保ちます。

品質評価が失敗する

QualityRun と上限付き Finding は永続化されます。対応済み Master ゲートが下流作業を停止する場合はありますが、共通の自動修復が続くわけではありません。

Analytics バインディングの 1 つが失敗する

バインディングごとの診断情報は表示され続け、成功したバインディングは固有の出力を保持できます。該当する場合、実行全体は部分成功のままです。

監視接続が切れる

正規実行へ再接続するかポーリングしてください。ブラウザーストリームの切断は、キュー済み状態変更操作がワーカーまたは対象に到達しなかったことの証明ではありません。

05

生成される証拠

選択した経路と保持上限に応じて、フローは FileVersion と変換アイデンティティ、QualityRun、DatasetVersion、ReportVersion、AnalyticsRun、診断情報、成果物ハッシュ、Assurance へ投影された正規参照を保持できます。

06

現在の境界

これはオペレーターの作業経路であり、単一の自動ワークフローではありません。Pipeline は Dataset を自動作成せず、スケジュールは現在実行をディスパッチせず、仮想 DatasetVersion は稼働中の行を固定しません。また、共通のロールバックまたは正確に一度の保証はありません。

関連する視点

データ運用 明示的なスコープと実行コンテキストの下で、接続、検査、変換、実行を行います。

すべてのコネクターを同一のクエリ／書き込みモデルに均一化することなく、異種 Sources と制御されたファイルから、管理テーブル、品質確認、永続化された実行履歴へ進みます。

→ データ品質 品質を、実行後の文書ではなく実行そのものの一部にします。

Data Quality は Source 指向の期待値を、明確な合格条件、永続化された QualityRun、制限された失敗証拠を持つ再実行可能な SQL アサーションへ変換します。

→ ガバナンスされた Dataset データ定義を、明示的なリネージュを持つバージョン管理資産へ変換します。

Dataset は探索用の SQL と再利用可能なデータ契約を分離します。安定した識別情報、不変のバージョン、セマンティックなメタデータにより、ソースリネージュを隠さずに Report の制御された基盤を作ります。

→ 制御された Analytics データ契約を固定する。実行をガバナンスする。結果を説明する。

制御された Analytics は、Report を正確な DatasetVersion に結び付け、Query Context をサーバー上で検証し、対応済み結果の背後にある権限、RLS、フィルター、バインディング、アーティファクトのコンテキストを保持します。
