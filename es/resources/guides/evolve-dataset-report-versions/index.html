Guía operativa · Evolución de versiones

Evolucione un Dataset y un informe sin reescribir su historial.

Utilice este flujo cuando cambien el SQL propiedad del Dataset, el linaje de Source, el esquema, las columnas o sus metadatos y un informe existente deba decidir si acepta el nuevo contrato.

Comenzar por la decisión de aceptación →

01

Pregunta de decisión

¿Dataset v3 conserva las columnas, tipos, granularidad y significado de Source que requiere el informe, o debe Report v5 permanecer fijado a Dataset v2 hasta que se rediseñe el contrato analítico?

02

Objetos y controles utilizados

Dataset, DatasetVersion y DatasetColumn contienen el contrato de datos base. ReportVersion contiene la intención analítica y las vinculaciones exactas a DatasetVersion. AnalyticsRun registra una ejecución bajo el gobierno actual.

01Ciclo de vida de Dataset e identidad inmutable de DatasetVersion

02SQL normalizado, linaje de Source, columnas, tipos y metadatos de perfil conocidos

03Dimensiones y métricas de Report, gráfico, filtros persistentes y vinculaciones exactas

04Compilación, permisos, RLS y contexto de vista previa propiedad del servidor

03

Flujo de aceptación

Una nueva DatasetVersion nunca desplaza por sí sola una ReportVersion existente.

  1. 01

    Crear la nueva DatasetVersion

    Guarde el contrato modificado de SQL/esquema/columnas propiedad del Dataset, preservando la identidad estable del Dataset y todas sus versiones anteriores.

  2. 02

    Comparar versiones exactas

    Revise la diferencia de SQL normalizado, el linaje de Source, las columnas añadidas/eliminadas/modificadas, los tipos, la nulabilidad y los metadatos históricos no disponibles.

  3. 03

    Evaluar la compatibilidad analítica

    Confirme la granularidad prevista, las dimensiones y los campos de Source que requiere cada métrica; no deduzca compatibilidad únicamente porque coincidan los nombres.

  4. 04

    Abrir un nuevo borrador de informe

    Mantenga inmutable la ReportVersion anterior y vincule el borrador a la DatasetVersion candidata.

  5. 05

    Validar y compilar

    Resuelva los metadatos, valide Query Context y compile SQL de solo lectura propiedad del servidor para la ruta de dialecto admitida actualmente.

  6. 06

    Previsualizar bajo gobierno

    Ejecute una vista previa acotada con el alcance actual de permisos y RLS, y revise los diagnósticos en lugar de aceptar únicamente la validación del esquema.

  7. 07

    Guardar la ReportVersion aceptada

    Persista la nueva vinculación solo después de aceptarla; las AnalyticsRuns posteriores apuntan a ese par exacto de ReportVersion y DatasetVersion.

04

Rutas de fallo y resultado parcial

Rechazar una candidata no modifica la versión anterior del informe orientada a producción ni sus vinculaciones históricas de ejecución.

Campo eliminado o modificado

La compilación o validación semántica bloquea el borrador; rediseñe la dimensión o métrica en lugar de modificar la ReportVersion anterior.

La vista previa difiere de forma inesperada

Trate la deriva de filas activas, el cambio de Source, el alcance de filtros/RLS y el cambio de contrato como hipótesis separadas; una DatasetVersion virtual no es una instantánea de filas.

La vinculación múltiple es parcial

Revise el diagnóstico de cada vinculación y preserve el estado parcial; no certifique el informe basándose únicamente en la vinculación correcta.

05

Evidencia producida

La comparación de versiones, la identidad de DatasetVersion aceptada, la vinculación inmutable de ReportVersion, los hashes de compilación/configuración/filtros/RLS y la AnalyticsRun posterior constituyen la cadena registrada del cambio admitido.

Report v4 → Dataset v2 · Report v5 → Dataset v2 · Report v6 → Dataset v3

06

Límite actual

La comparación cubre el SQL, esquema, columnas, metadatos y linaje registrados; no inventa un impacto empresarial descendente universal. Las métricas de Analytics, RLS y los permisos de Report permanecen fuera del agregado base de Dataset, y las filas históricas exactas requieren un artefacto o un contrato explícito de instantánea materializada.

Perspectivas relacionadas

Datasets gobernados Convierta definiciones de datos en activos versionados con linaje explícito.

Dataset separa el SQL exploratorio de un contrato de datos reutilizable. Su identidad estable, sus versiones inmutables y sus metadatos semánticos crean una base controlada para Reports sin ocultar el linaje de origen.

→ Analítica controlada Fije el contrato de datos. Gobierne la ejecución. Explique el resultado.

La analítica controlada vincula un Report con DatasetVersion exactas, valida el contexto de consulta en el servidor y conserva los permisos, RLS, filtros, vinculaciones y artefactos que explican un resultado admitido.

→ Guía operativa · Ciclo de vida de los datos De una entrada conocida a un resultado analítico gobernado.

Utilice este flujo cuando un resultado analítico recurrente deba conservar contexto conocido de entrada, calidad, versión, permiso y ejecución entre módulos canónicos independientes.

→ advanexus Assurance Investigue un resultado admitido a través de la evidencia disponible que lo respalda.

Assurance es una capa de lectura optimizada y consciente de los permisos para explorar evidencia operativa admitida. No sustituye la fuente canónica ni crea un historial que nunca fue registrado.
